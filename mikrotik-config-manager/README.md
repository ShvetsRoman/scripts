# MikroTik Configuration Manager — v0.0.41

Rust CLI для **чистої установки RouterOS 7** на основі TOML-профілів. Профілі є взаємозамінними: поведінку визначає конфігурація, а не назва каталогу. Доступні приклади `hap-ac` (реальне обладнання) та `test` (VirtualBox CHR).

## Початок роботи

```bash
cargo run -- --version
cargo run -- list
cargo run -- plan hap-ac
cargo run -- plan test
cargo run -- plan hap-ac interfaces
cargo run -- plan hap-ac services
./scripts/check.sh
```

`plan` не виконує команд RouterOS; `apply` заблоковано. Для початкової інсталяції використовують `build` із зовнішніми секретами, а потім контрольований `upload` і, лише за явним рішенням, `--reset`. Розділ [Чиста установка](docs/INSTALLATION.md) містить попередження щодо втрати конфігурації.

## Основні правила

- Порти `etherN`, `sfpN`, `wlanN` задаються **лише** в `interfaces.toml`; невказаний порт не налаштовується. Номер `N` додатний, фіксованого переліку немає.
- Фізичний `sfp1` на `hap-ac` присутній і навмисно вимкнений (`enabled = false`). У `test` такого запису немає.
- Management здійснюється через LAN bridge за поточним `network.toml`; WAN та критичні інтерфейси перевіряються окремо.
- `services.ssh.limit_to_lan` та `services.winbox.limit_to_lan` керують `address=` для сервісів; захист Firewall діє окремо.
- `wireless.driver` **потрібно звірити** з фактично встановленим пакетом на маршрутизаторі.
- Усі `.secrets` і створені RSC із паролями залишаються приватними. Ніколи не публікуйте їх і не додавайте до Git.
- Згенерований PLAN не є готовою інструкцією повторного імпорту: призначення — чиста установка.

## Статус

Поточна версія — **v0.0.41 Stable**. Попередня стабільна версія — **v0.0.40 Stable**. Етапи v0.0.40 Stage 1–6 пройшли локальну перевірку `5/5 PASS` за підтвердженням користувача. Для кожної подальшої зміни необхідно повторити `./scripts/check.sh`. Підсумкову кількість Rust-тестів і результат п’яти етапів визначає **поточний** журнал; історичні числа не є релізним контрактом. Автоматичні тести не підтверджують живе застосування на MikroTik.

## v0.0.40 Stage 1 — Architecture & Error Contracts (RC)

Винесено формування типізованого набору компонентів у `Prepared::components()`;
прибрано повторну перевірку формату фізичного ID після попередньої перевірки.
Додано профіленезалежну регресію детермінованості `plan`/`plan all`.
Робочі RouterOS-команди, CLI, SCP/SSH та RESET не змінювалися.
Цей RC потребує запуску `./scripts/check.sh` перед переходом до Stable.

## v0.0.40 Stage 6 — Configuration & Localization Final Audit (RC)

Перевірено наявність повних незалежних профілів TOML, сувору схему Serde,
паритет ключів української та англійської локалізацій і типізовані причини помилок.
Виправлено застарілий статус README та додано релізні регресійні перевірки.
Функціональний код, параметри профілів і команди RouterOS не змінювалися.
Перед фіксацією Stable обов'язковий успішний запуск `./scripts/check.sh`.

## v0.0.40 Stage 7 — Stable Release

Версію v0.0.40 зафіксовано після підтвердження 5/5 PASS для Stage 6.
Статус RC у попередніх розділах є історією етапів, а не статусом поточного релізу.
Кількість Rust-тестів визначає фактичний журнал останнього запуску `./scripts/check.sh`;
без цього журналу кількість не стверджується. Функціональний код цього етапу не змінювався.

## v0.0.41 Stage 1 — Localization Validation Contracts

Завантажувач `Messages::load()` відхиляє повторні та порожні ключі через типізовані `LocaleError::DuplicateKey` і `LocaleError::EmptyKey`. Формат коректних перекладів та CLI не змінено. Етап потребує нового локального `./scripts/check.sh` 5/5 PASS.

## v0.0.41 Stage 5 — Release Readiness Audit (RC)

Перевірено узгодженість версії Cargo/README, контрактів п’ятиетапного `scripts/check.sh`,
наявність 30 TOML-файлів незалежних профілів і паритет локалізацій `uk/en`.
Поточний статус README і його релізний тест синхронізовано зі Stage 5 RC.
Від користувача отримано підтвердження `5/5 PASS` для Stage 4 Rustfmt Fix RC;
поточний Stage 5 RC потребує окремого повторного запуску `./scripts/check.sh`.
Робочі CLI, PLAN/BUILD, SSH/SCP, RESET, Firewall/NAT/WireGuard і RouterOS-команди не змінені.

## v0.0.41 Stable — фіналізація

Реліз сформовано з Stage 5 Verified Source Refresh RC після підтвердження користувачем `5/5 PASS`.
Поточні контракти CLI, PLAN/BUILD, SSH/SCP, RESET і RouterOS збережені без змін.
У цьому архіві `Cargo.lock` не містить повного дерева залежностей; Cargo доповнює його
під час локального запуску. Для відтворюваних збірок необхідно зафіксувати
створений Cargo повний `Cargo.lock` та перевірити `cargo build --locked`.
Підтвердження 5/5 PASS стосується базового RC, а не змін релізної документації.
