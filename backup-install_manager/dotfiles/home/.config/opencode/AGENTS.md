# Загальні правила розробки

## Мова

- Спілкуватися українською мовою.
- Пояснення та звіти надавати українською.
- Коментарі у створених конфігураційних файлах писати українською.
- Назви змінних, функцій та API залишати відповідно до
  стандартів конкретної мови програмування.

## Загальні принципи

- Перед змінами досліджувати структуру проєкту.
- Не змінювати поведінку без прямої необхідності.
- Виправляти тільки підтверджені дефекти.
- Не видаляти наявні можливості без погодження.
- Не створювати зайві абстракції та залежності.
- Не дублювати наявний функціонал.
- Дотримуватися архітектури проєкту.
- Враховувати сумісність із наявними компонентами.

## Робота з файлами

- Перед редагуванням читати повний файл.
- Перевіряти пов'язані файли та залежності.
- Не перезаписувати файли без перевірки їхнього вмісту.
- Не змінювати конфігурацію користувача поза межами проєкту.
- Не видаляти резервні копії та користувацькі дані.
- Не зберігати секрети, токени та паролі у Git.

## Робота з Git

- Перед змінами перевіряти git status.
- Не перезаписувати незакомічені зміни користувача.
- Не виконувати git push.
- Не створювати коміти без запиту.
- Після роботи показувати git diff.
- Не видаляти гілки без погодження.

## Тестування

- Визначати наявні засоби тестування.
- Запускати відповідні перевірки після змін.
- Не пропускати негативні сценарії.
- Розділяти PASS, FAIL, SKIP та TIMEOUT.
- Не називати проєкт стабільним, якщо обов'язкові
  перевірки не завершені.
- Не приховувати помилки тестування.

## Безпека

- Не запускати команди sudo без погодження.
- Не змінювати системні налаштування без погодження.
- Не виконувати незворотні операції без погодження.
- Не читати секретні файли без необхідності.
- Не передавати приватні дані зовнішнім сервісам.

## Звіти

Після виконання завдання надавати:

1. Що було досліджено.
2. Що саме змінено.
3. Які файли створено або змінено.
4. Які перевірки виконано.
5. Результати PASS / FAIL / SKIP / TIMEOUT.
6. Відомі обмеження та наступні кроки.

## Принцип змін

Перевага надається мінімальним, перевіреним
та зворотним змінам.
