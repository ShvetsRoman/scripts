# Безпека

## Шляхи

  path_ok_rel — забороняє .., ., абсолютні шляхи, ./, нові рядки
  path_ok_abs — забороняє .. і symlink у будь-якому компоненті шляху
  safe_dir    — те саме для каталогів перед очищенням

## Файлові операції

  fs_copy    використовує --safe-links; дерево із symlink відхиляється
  fs_protect завжди без --delete
  apply      перед записом робить backup у backups/<group>/
  recovery   для нових знімків використовує manifest.tsv і точний шлях
  --sync-delete разом із --no-backup заборонено

## Архіви

Перед публікацією і перед restore архів проходить archive_safe.py verify:

  - перший компонент шляху — dotfiles/
  - відсутність .., ., абсолютних шляхів, зворотних слешів, NUL
  - відсутність symlink і hardlink
  - відсутність дублікатів
  - сумарний розмір не більше 2 ГБ, кількість не більше 100k

Перед заміною dotfiles/ створюється захисний архів поточного стану.

## Оновлення коду

update_safe.py оновлює ЛИШЕ:

  setup.sh, README.md — верхній рівень
  lib/, modules/, tests/, tools/, docs/ — каталоги

Ніколи не торкається dotfiles/, backups/, archives/, logs/, config/.
Атомарний запис через os.replace, повний rollback при помилці,
бекап старого коду у backups/updates/code-<timestamp>/.

## Recovery V2 (v1.2.0)

Нові `backups/recovery/<ID>/` містять `manifest.tsv`, `data/`, `checksums.json`.
Останній фіксує SHA-256 файлів та маніфесту, розмір і список каталогів/файлів.
Перед відновленням запущено `recovery verify`, зміна або відсутність файлів блокує restore.
Копії v1.1.0 із маніфестом, але без checksums, можна відновити після попередження і підтвердження; код `verify` = 3.
Копії без `manifest.tsv` автоматично відновлювати не можна.

Це перевірка цілісності, а не криптографічна автентифікація: вона не захищає від зловмисника, який контролює файли й сам індекс SHA-256.

## v1.3.0: межі автоматичного rollback

Перед оновленням існуючої цілі `fs_protect` створює snapshot та SHA-256. Якщо копіювання або перевірка даних завершується з помилкою, `apply_rollback` намагається відновити **тільки поточну ціль**; попередні успішні зміни в інших джерелах не скасовуються. За `--no-backup` rollback існуючих цілей недоступний. Переривання `SIGKILL`, аварійне завершення ядра або вимкнення живлення не гарантують виклик rollback. Користувач повинен мати зовнішні незалежні backup критичних даних.

Перевірка SHA-256 гарантує виявлення випадкової невідповідності між поточними файлами і записаними контрольними сумами, але не доводить автентичність джерела; це не криптографічний підпис архіву.
