## v1.3.0 — Status counters & explanations fix

- Відновлено коментарі до `[CHANGED]`, `[NEW]` і `[DEL]` у `status`, `diff`, `verify`, включно з вкладеними файлами й каталогами.
- Лічильники `[NEW]` і `[DEL]` включають як цілі записи з `sources.conf`, так і відсутні **вкладені елементи** в каталогах `[CHANGED]`. Цілий відсутній підкаталог рахується як один елемент, а не як сума його вмісту.
- `status` підраховує `[UNTRACKED]` окремо як «поза реєстром»; це не те саме, що `[DEL]` (для незареєстрованих файлів шлях у HOME невідомий).
- Суми статусів можуть бути більшими за кількість записів `sources.conf`, оскільки `[CHANGED]` — це батьківський запис, а вкладені `[NEW]`/`[DEL]` — окремі знахідки.
- Додано регресійний `test-status-counts.sh`, який перевіряє точні підсумки та пояснення для `status`, `diff`, `verify`; звичайні відмінності як і раніше повертають код 0.

## v1.3.0 — Status / Diff / Verify UX fix

## v1.3.0 — Stability & Logging (14.10.2026)

- Нова команда `dotfiles backup changed [ШЛЯХ...]`: порівнює за checksum, копіює лише нові/змінені записи, пропускає незмінені; меню використовує ту ж реалізацію.
- Логування у файл: часовий штамп, PID, run ID; команди `logs path|tail [N]`.
- Best-effort rollback **окремого** об'єкта після помилки `fs_copy` або перевірки, з використанням попереднього SHA-256 backup; частково створені нові об'єкти видаляються.
- Нові snapshots усіх груп `fs_protect` містять manifest та SHA-256. Команди `backups list GROUP`, `backups verify GROUP ID`.
- `recovery plan ID [REL...]` і `recovery restore ID [REL...]` — вибіркове відновлення за точним rel з manifest.
- `maintenance rotate dotfiles|recovery|installer KEEP` — ручна ротація за кількістю, із підтвердженням та dry-run.
- Додано 6 нових регресійних тестів: changed, rollback, selective recovery, rotation, backup integrity, logging. `test` як раніше ніколи не викликає `clear`.
- Обмеження: немає атомарного rollback для **всього batch**, завершення SIGKILL, аварійне вимкнення живлення не гарантують відновлення. `--no-backup` вимикає rollback для існуючих цілей. У v1.3.0 ротація не автоматична. Підсумки рахують записи, а не файли.

## v1.2.0 — Recovery V2 / Verify / Plan / Summary (14.10.2026)

- Додано контрольні суми SHA-256 для нових recovery-знімків (`checksums.json`). Перед restore перевіряються файли й manifest, помилки блокують запис.
- `recovery verify ID` дає код 0 для перевіреного, 3 для старого без checksums, 1/2 для пошкодженого або некоректного знімка. Старі знімки із правильним manifest лишаються доступні для підтвердженого restore.
- `dotfiles verify [ШЛЯХ...]` — порівняння HOME і dotfiles із підсумком та коректними кодами виходу, без запису.
- `dotfiles plan backup|restore [ШЛЯХ...]` — планування COPY/UPDATE/SKIP/MISSING/ERROR, попередження про видалення із `--sync-delete`; без змін файлів.
- Статистика backup/restore і recovery restore: змінено, не змінено, відсутнє, помилки.
- Єдина `ui_clear` контролює очищення терміналу. В `./setup.sh test` `clear` вимкнено для всіх підпроцесів; для окремих команд — `SETUP_NO_CLEAR=true`.
- 4 нові регресійні тести (plan, verify, recovery-integrity, no-clear), збережено зворотну сумісність із `sources.conf` v1.1.0.

## v1.0.1 — Critical Fixes (14.10.2026)

### Коригування після перевірки ShellCheck

- Усунуто два попередження `SC1112`: для рядків з українським типографським апострофом використано подвійні лапки.
- Для `SC2034` додано адресні директиви з поясненнями: глобальні змінні керування CLI і результат `APPLY_RESULT` читаються іншими `source`-модулями.
- Логіка встановлення, синхронізації та recovery не змінена, номер версії залишився `1.0.1`.


- Усунено запис через symlink у призначенні; покращено перевірки абсолютних шляхів (`/tmp/..`, `/tmp/.`, `//`).
- `apply` тепер повертає 0 при успіху і використовує `APPLY_RESULT=changed|unchanged|skipped`.
- `--sync-delete --no-backup` заборонено до виконання будь-якої файлової операції.
- `backup-src` / `restore-src` та `sources add/remove` більше не створюють і не змінюють дані у `--dry-run`.
- Recovery містить `manifest.tsv`, що прив'язує backup до точного початкового шляху.
- Старі recovery-знімки без manifest **навмисно не відновлюються автоматично**; їх можна переглянути вручну.
- Створені tar.gz перевіряються перед публікацією; якщо у dotfiles є symlink, створення завершується явною помилкою.
- Реєстр sources.conf проходить валідацію при завантаженні (5 полів, безпечні шляхи, дублікати).
- `sources add NAME MODE SRC DST [GROUP]` і старий формат `sources add MODE SRC DST`; `sources remove NAME`.
- Додано відсутній пункт `Sources → Add`, актуалізовано тести і документацію.

Важливо: файлові symlink у джерелі та tar-архівах не підтримуються у v1.0.1 задля безпеки. Перед роботою зробіть незалежний backup критичних даних.
