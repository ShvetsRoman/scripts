# Backup-Sync V2.6.3

Модульний rsync/SSH backup/sync для PC <-> SERVER.

## Основні можливості

- `up` — PC -> SERVER (mirror), `down` — SERVER -> PC
- `--dry-run`, `--host` (SSH alias), `--yes`
- **recovery в обидва боки**: перед перезаписом/видаленням стара версія файлу зберігається (UP — на сервері, DOWN — локально)
- **захист від масового видалення**: `MAX_DELETE`, відмова mirror із порожнього джерела, попередній аналіз перед запитом
- `--delete-delay`, partial transfers, глобальні та поканальні excludes, необов'язкові `-H/-A/-X`
- verify через rsync (+ checksum), окремий код виходу для «знайдено відмінності»
- XDG logs, `flock` від паралельного запуску, SSH keepalive/timeouts
- local/remote preflight; перевірка вільного місця за обсягом реальної передачі (dry-run) і лише на стороні
  призначення (`--no-space-check` для вимкнення)
- `REMOTE_DIR` створюється лише після підтвердження: скасований запуск не лишає слідів на сервері
- cleanup logs/recovery (з підтримкою `--dry-run`) і необов'язкове автоочищення recovery після успішного запуску
- жодних «тихих» виходів: неочікувана помилка завжди друкується з рядком і командою
- **remote-lock між ПК**: два запуски (з різних комп'ютерів) не можуть одночасно змінювати один сервер
- коректне завершення по Ctrl-C/TERM (код 130/143): фінальні повідомлення в лозі, lock знімається
- кожен рядок логу має часову мітку `HH:MM:SS`; нові каталоги стану/логів створюються з правами 700,
  файли логів — 600 (логи містять імена ваших файлів; уже наявні каталоги не змінюються)
- лог-файл без ANSI-кольорів і проміжного прогресу rsync; кольори в консолі лише в TTY (`NO_COLOR` вимикає)

## Вимоги

bash ≥ 4.4 (перевіряється при старті), rsync (локально й на сервері), ssh, flock, `setsid` (util-linux; бажано, див. нижче), GNU find/awk/sed/df. На сервері достатньо POSIX `sh`
(`mkdir`, `find`, `head`, `sed`, `df`, `rmdir`).

## Запуск

```bash
chmod +x backup-sync.sh tests/*.sh

./backup-sync.sh up --dry-run
./backup-sync.sh up
./backup-sync.sh up --host serv
./backup-sync.sh up -y --max-delete 2000
./backup-sync.sh up --no-space-check     # без перевірки місця
./backup-sync.sh up --no-recovery        # без збереження старих версій (небезпечно: mirror видаляє файли)
./backup-sync.sh down --recovery         # примусово з recovery, навіть якщо вимкнено в конфігу
./backup-sync.sh down
./backup-sync.sh verify up
./backup-sync.sh verify both
./backup-sync.sh verify --host serv down   # напрямок можна ставити будь-де серед опцій
./backup-sync.sh cleanup --dry-run     # лише показати, що буде видалено
./backup-sync.sh cleanup
./backup-sync.sh help
```

Без `-y` перед підтвердженням виконується dry-run і показується, скільки файлів оновиться та
яких саме буде видалено. Без TTY (cron) потрібен `-y` або `--dry-run`.

## Коди виходу

| Код | Значення |
|-----|----------|
| 0 | успішно |
| 1 | помилка (або є каталоги з помилками) |
| 2 | некоректні аргументи |
| 3 | `verify`: знайдено відмінності (помилок немає) |
| 4 | користувач скасував операцію |

`rsync` rc=24 («файли зникли під час передачі») вважається попередженням, не помилкою.

## Безпека

`up` є mirror-напрямком і використовує `--delete-delay`. Захисти:

- **MAX_DELETE** (за замовч. 500 на каталог; `--max-delete N`, `0` = без ліміту). При перевищенні
  rsync пропускає видалення, каталог отримує FAIL, код виходу 1.
- **Порожнє джерело**: якщо локальний (UP) або remote (DOWN з `DELETE_ON_DOWN=true`) каталог
  порожній, він пропускається. Дозволити: `--allow-empty` / `ALLOW_EMPTY_SOURCE=true`.
- **Recovery не пропускається мовчки**: якщо recovery-каталог не вдалося підготувати, цей каталог
  не синхронізується.
- Конфіг валідується до будь-яких дій (`RECOVERY_ROOT`, `BACKUP_DIRS`, шляхи, числа, булеві).

`down` за замовчуванням **не видаляє** зайві локальні файли (`DELETE_ON_DOWN=false`).

## Ctrl-C і запис логу

Вивід скрипта йде через `tee` у лог-файл. Щоб при Ctrl-C/`kill` скрипт завершувався коректно (код 130/143,
фінальні повідомлення є і в консолі, і в лозі, remote-lock знімається), `tee` запускається у **власній
сесії через `setsid`**: сигнали, надіслані групі процесів скрипта, до нього не доходять. Покладатися лише на
«`tee` ігнорує сигнали» не можна: успадкування ігнорування через `exec` відрізняється між версіями bash
(у деяких SIGINT повертається до типової поведінки, і `tee` гине раніше за скрипт).

Без `setsid` (або з `BACKUP_SYNC_NO_SETSID=1`) діє запасний режим: SIGPIPE ігнорується, а на сигналі скрипт
безумовно відключається від `tee`, пише підсумок у консоль і дописує його в лог-файл напряму (лог може бути
неповним). Режим видно в підсумку запуску (`Запис логу: …`). Якщо `tee` вбито ззовні (`kill -9`) посеред роботи,
скрипт завершиться по SIGPIPE.

## Вільне місце

Перевірка виконується лише для реальних `up`/`down` (не для `--dry-run`, `verify`, `cleanup`) **до** запиту
підтвердження і лише на **стороні призначення**: `up` → сервер, `down` → локальний диск.

- `SPACE_CHECK_METHOD="dry-run"` (за замовчуванням): скрипт робить один dry-run по всіх каталогах і бере з `--stats`
  обсяг, який rsync справді передасть. Потрібно: **обсяг + запас `MIN_FREE_MIB`** (запас має лишитись вільним
  *після* передачі). Той самий dry-run показується в попередньому аналізі перед підтвердженням, тож дерево
  сканується один раз.
- `SPACE_CHECK_METHOD="threshold"`: лише запас, без dry-run (швидше, але не знає обсягу).
- Якщо обсяг для каталогу оцінити не вдалося, для нього враховується лише запас (з попередженням).
- Якщо `REMOTE_DIR` ще не існує, беруться дані найближчого існуючого батьківського каталогу.
- Оцінка консервативна: видалення (без recovery вони звільняють місце) не враховуються.

## Виключення (excludes)

| Файл | Дія |
|------|-----|
| `config/exclude.conf` (`EXCLUDE_FILE`) | глобальний: для кожного каталогу з `BACKUP_DIRS` (лише безпечне: кеші, venv…) |
| `config/exclude.d/<каталог>.conf` (`EXCLUDE_DIR`) | лише для цього каталогу (`/` в імені → `__`: `A/sub` → `A__sub.conf`) |

`build/`, `target/`, `dist/` тепер у `exclude.d/01_project.conf` і `03_work.conf`, а не в глобальному файлі:
раніше вони виключали однойменні каталоги й у `Documents`, `Pictures`, `Music`. **Зверніть увагу:** якщо у
вас там є такі каталоги, вони тепер синхронізуватимуться. Однакові виключення застосовуються в sync,
dry-run-аналізі та `verify`. Виключені файли на приймачі не видаляються (немає `--delete-excluded`).

## Що ще зберігати: `-H`, `-A`, `-X`

За замовчуванням вимкнено (лише `--archive`). У конфігу: `RSYNC_PRESERVE_HARDLINKS` (`--hard-links`),
`RSYNC_PRESERVE_ACLS` (`--acls`), `RSYNC_PRESERVE_XATTRS` (`--xattrs`). Прапорці діють однаково в sync,
аналізі та `verify`. Перед початком роботи скрипт читає `rsync --version` **обох** сторін і відмовляється,
якщо потрібної можливості немає (`no ACLs`); якщо формат `--version` старий і визначити неможливо — лише
попереджає. На Android-сервері ACL/xattrs зазвичай недоступні.

## Remote-lock (кілька ПК → один сервер)

Локальний `flock` не бачить інших комп'ютерів, а два одночасні mirror-запуски з `--delete-delay`
можуть видаляти файли один одного. Тому `up`, `down` і `cleanup` (без `--dry-run`) беруть lock на сервері:
атомарний `mkdir $REMOTE_DIR/.backup-sync.lock` із файлом `owner` (хост, користувач, pid, час).

- `verify` і `--dry-run` нічого не змінюють і lock не беруть.
- Якщо lock зайнятий, скрипт завершується з кодом 1 і показує власника.
- Lock знімається при будь-якому завершенні (успіх, помилка, Ctrl-C, TERM) — і лише якщо він досі наш.
- Після аварії (`kill -9`, відключення живлення) lock лишається: перевірте, що інший запуск не триває,
  і запустіть з `--break-lock` (або вручну `ssh serv rm -rf $REMOTE_DIR/.backup-sync.lock`).

## SSH

- У прямому режимі (`SSH_IP`/`SSH_KEY`) додається `-o IdentitiesOnly=yes`: використовується лише вказаний
  ключ, а не всі з ssh-agent (інакше сервер може відхилити з'єднання через забагато спроб).
- `SSH_STRICT_HOST_KEY_CHECKING` (`""`, `yes`, `accept-new`, …) — політика перевірки ключа сервера. Через
  `BatchMode=yes` перше підключення до невідомого сервера без запису в `known_hosts` не вдається:
  підключіться вручну один раз або задайте `accept-new`.
- Шляхи з пробілами в `--rsh` беруться в лапки у формі, яку розуміє rsync.

## Recovery і відновлення

Окремий каталог **для кожного** запуску і **для кожного** каталогу з `BACKUP_DIRS`
(тому однакові імена файлів у різних каталогах не затирають одне одного):

```text
UP   : $REMOTE_DIR/$RECOVERY_ROOT/YYYY-MM-DD_HH-MM-SS/<каталог>/...
DOWN : $LOCAL_RECOVERY_DIR/YYYY-MM-DD_HH-MM-SS/<каталог>/...   (за замовч. ~/.local/state/backup-sync/recovery-down)
```

Порожні каталоги після запуску прибираються. **Відновлення** — звичайне копіювання назад, напр.:

```bash
# файл Documents/a.txt із запуску 2026-10-18_14-00-00 (UP) назад на сервері
ssh serv 'cp -a "$REMOTE_DIR/.backup-sync-recovery/2026-10-18_14-00-00/Documents/a.txt" "$REMOTE_DIR/Documents/a.txt"'

# локально (DOWN)
cp -a ~/.local/state/backup-sync/recovery-down/2026-10-18_14-00-00/Documents/a.txt ~/Documents/a.txt
```

### Вмикання та вимикання recovery

| Де | Що | Дія |
|----|----|-----|
| конфіг | `RECOVERY_ENABLED` | загальний вимикач (`false` — recovery вимкнено повністю) |
| конфіг | `RECOVERY_UP_ENABLED` | recovery для `up` (копії на сервері) |
| конфіг | `RECOVERY_DOWN_ENABLED` | recovery для `down` (локальні копії) |
| CLI | `--recovery` | увімкнути на цей запуск (перекриває **всі** перемикачі конфігу) |
| CLI | `--no-recovery` | вимкнути на цей запуск |

Recovery діє для напрямку, лише якщо ввімкнені і загальний, і його власний перемикач. Якщо прапорців
кілька, виграє останній. Коли recovery вимкнено, скрипт явно попереджає про це в підсумку режиму та в запиті
підтвердження: перезаписані й видалені (mirror!) файли **втрачаються безповоротно**. У `--dry-run` копії не
створюються в жодному разі. Ручний `cleanup` працює завжди, тож раніше збережені копії можна прибрати й тоді,
коли recovery вимкнено. Автоочищення діє лише для напрямку з увімкненим recovery.

Дні зберігання: `KEEP_RECOVERY_DAYS` (сервер), `KEEP_LOCAL_RECOVERY_DAYS` (локально). Видаляються лише
каталоги з іменем-таймстемпом, і лише старші за цей термін.

### Автоочищення (необов'язково)

За замовчуванням recovery чиститься вручну: `./backup-sync.sh cleanup` (`--dry-run` — лише показати).
Щоб чистити автоматично, задайте `AUTO_CLEANUP_RECOVERY=true` у конфігу або запускайте з `--auto-cleanup`
(`--no-auto-cleanup` вимикає для одного запуску). Правила:

- виконується лише після **успішного** `up`/`down` (будь-яка помилка → пропускається, бо старі копії
  можуть знадобитись);
- чистить recovery того напрямку, який щойно записував: `up` → серверний, `down` → локальний;
- не виконується в `--dry-run` і при `RECOVERY_ENABLED=false`;
- працює під remote-lock і ніколи не торкається recovery поточного запуску;
- у виводі видно, що саме видалено;
- збій очищення лише дає попередження — результат і код виходу синхронізації не змінюються.
